# 《请把我画出去》领域规则层实验

> 日期：2026-08-12
> 范围：首次触碰、雨城三种调查方法、第一世界三种解法、四线索至终局门槛
> 结论：通过；受管回合现在零模型请求、结果可复现，自由行动仍保留 AI 叙事。

## 实验问题

原实现把剧情协议交给模型生成，语义很灵活，但同一回合可能同时出现互相冲突的物品、事实、地图和数值命令。最明显的例子是“撤销键”在文案上是一枚有三次机会的物件，协议却把它保存成 `count=3`；第一次撤销也没有要求一个可验证、不可重复的永久代价。三条首世界路线和三条首线索依赖翻译后的地点名与模型同时写 item/fact，存在重复领取、跨路线跳转和里程碑漂移风险。

## 改造边界

本地领域裁判只接管有精确经济或连续性后果的动作：唯一道具、首次登场、路线锁、一次性线索、危险恢复和章节 checkpoint。普通观察、交谈、探索与自定义世界仍保持 AI 自由生成。

当前 22 条规则覆盖：

- 首次触碰悬雨，并立刻揭示“余力”及其消耗；
- 雨城的路人、空白边缘、出口三种调查方法及不同代价；
- 撤销键获取（普通取得与跳入颜色两个代价分支）；
- 进入无边处；
- 小残按“可见外形—名字来源—关系—入队”顺序登场；
- 飞城、语言王国、七年会议三条稳定首路线；
- 重量、空位、离开三条首线索各自有三种解法、不同状态后果，并且只结算一次；
- 免费撤销拒绝；
- 明确永久忘掉“悬停的雨”后完成第一次撤销。

命中这些规则时不再向模型发送请求：本地成功正文、状态变化、事实和下一组选项在同一次事务中产生。只有不命中规则的观察、交谈、探索和自由输入才调用 AI。这样领域层不只是“事后覆盖模型命令”，而是真正成为关键动作的权威执行器。

## 开场对照实验

改造前，玩家需要“开始—阅读—再选一次”才得到第一条可验证事实；三条雨城选项和三种首世界解法在状态上容易收敛成同一结果，HUD 还会提前展示三个没有语境的数值。改造后：

- 入口按钮本身就是第一次有效动作；一次点击后立即写入 `rain-is-pixels`，余力从 65 降为 61；
- 雨城三种方法分别留下 `passerby / blank-edge / direct-door`，产生三组不同的状态结果；
- 飞城三种解法分别留下 `direct-catch / remnant-hatch / public-service`，都只奖励一条重量线索，但三组状态结果互不相同；
- HUD 首次只揭示“余力”，选择路人后才增加“被发现”，身份受损或取得撤销键后再揭示“我还是我”；旧存档在场景 3 后回退为完整 HUD；
- 开场长情境必须读到最后一页才出现选择与自由输入，不再让玩家跳过前置因果。

`npm run test:opening` 的机械结果为：第一事实 1 次点击；三条雨城方法事实互异、状态元组互异；三种飞城解法事实互异、状态元组互异，并且每条路径的线索数都严格为 1。

## 自动对抗与长线结果

`npm run test:domain` 在每个受管回合注入恶意模型命令：把数值设到极端、添加 99 个假线索、跳到虚构地图、让未登场的默认七号入队、重写目标和时间、提前结束章节并给出错误选项。最终本地状态仍为：

- 撤销键数量 1，初始剩余 3，支付一次后剩余 2；
- 小残只在可见登场回合创建并成为唯一同行者；
- 第一世界路线固定为 `flying-city`；
- 重量线索数量 1，重复领取为零效果；
- `home-clue-count=1`、`first-coordinate-earned=true`、`coordinates-four=false` 均由行囊重建；
- 免费撤销不扣次数、不平息危险、不结束章节；明确代价后才原子完成。

`npm run test:campaign` 进一步使用真实协议解析器、reducer 和每回合序列化/恢复，跑过 19 个场景、19 次重载、4 个不同线索与终局门槛，最终 `finale=ready`。这证明状态机、存档恢复和结局条件能贯通；其中未受管段落使用确定性的作者式 AI 响应，因此它不冒充“线上模型内容质量必然稳定”的证据。

## 浏览器实玩结果

在 390×844 与 320×568、Cinematic Civic 中实际走过：触碰悬雨 → 路人调查 → 唯一撤销键 → 无边处 → 小残登场 → 飞城 → 公共服务解法 → 自由询问小残。

浏览器验证结果态与决策态互斥、受管结果不会在下一屏重复、冗余“请做出选择”和内部图片协议不会显示、开场受管路径产生 0 次 AI 请求，而第一项自由行动恰好产生 1 次 AI 请求。两种移动视口均无横向溢出。证据在 `_qa/ui/platform-layout-*.png` 与 `_qa/ui/caption-visibility/*.png`，脚本为 `_qa/capture-ui.mjs`、`_qa/caption-visibility.mjs` 和 `_qa/playthrough.mjs`。

## 对通用模式的新结论

1. 领域事务不只包括数值、物品和地图；如果一个关键事件同时改变目标、时间或章节 checkpoint，它们也必须在同一次本地事务中提交。
2. 受管回合的下一组选项也是状态结果。模型选项若与已提交状态不一致，会把玩家重新导向非法分支，因此模型的所有协议命令（包括 choices）都应丢弃，由 rule resolution 安装合法选项。
3. “已找到几条 / 是否已集齐”这类事实若只是稳定物品所有权的视图，应从行囊派生，不能让模型同时写 item 与 fact。
4. 固定但未登场的角色可由 party effect 创建，但只允许在同回合可见成功正文已经完成合法首次登场时发生。
5. 如果领域规则已经拥有完整、双语且可读的成功正文，就不应再调用模型“润色”一次；那会重新引入延迟、题外叙述和不确定性。模型应只服务于规则没有穷举的开放行动。
6. 数值不应在开局全部裸露。由玩家亲历的事实逐项揭示状态，比先展示三个抽象指标更容易建立因果。

本次先把这些结论固化在游戏文档和可执行验收中。确认线上体验后，再把“入口即动作、状态渐进揭示、受管动作零模型请求、方法后果分离”提升为通用技能合同，并用于其他电影式 RPG。
