# 《请把我画出去》战役与视觉导演实验记录

## 实验问题

旧版已经有领域规则，但完整游玩仍会混乱：必要剧情一部分依赖模型协议，一部分依赖本地状态；图片提示又从叙事文本二次概括。于是可能出现“文字已经换世界，画面仍像上一幕”“模型漏命令后主线停住”“同一线索重复获得”“危险事件插进受管结果”等问题。

本轮假设：把必要主线改成确定性战役事务，并让每次事务同时提交视觉快照，可以同时提高因果可靠性和画叙一致性；AI 只保留在开放行动层。

## 实验改造

1. 四个世界分别使用 `arrival → problem → solution → consequence` 四阶段，每阶段只有一次权威状态提交。
2. 四条线索采用稳定 ID 和唯一奖励；完成世界后自动回到无边处并保存检查点。
3. 四线索之后增加两道显式真相闸门：抹平者来源、出口不可逆代价；玩家确认后才开放最终出口。
4. 受管回合不调用模型，也不叠加独立危险事件；自定义输入会映射到当前阶段的一种合法方法，不能让战役卡死。
5. 每个关键相变同时提交 `StoryVisualBeat`，包含地点、动作、结果、主体、道具、环境、光线、连续性和排除项。生图提示只能由该快照生成。
6. 图片未就绪时保留旧图，但降低视觉权重并明确标记为“上一幕”；文字和下一步操作不等待媒体。

## 验证结果

- 纯逻辑长线测试完成 23 场、4 个世界、4 条线索和终局入口；每场后均序列化并重新加载存档。
- 390×844 与 320×568 两个真实浏览器视口均完整走通，各执行 4 次刷新恢复。
- 共生成 19 个权威视觉快照；快照与图片块一同持久化，提示中没有跨世界残留、蒙太奇或未登场人物授权。
- 受管主线没有出现独立危险检定、重复线索、协议泄漏或冗余“请做出选择”。
- 撤销代价改为从当前真实、未支付的记忆动态生成；重复支付会被拒绝，支付不会错误终止会话。
- 自动浏览器的媒体层使用确定性桩，因此已证明“叙事事务→画面提示→换幕界面”的合同；没有证明第三方生成模型每张图都能保持相同画风，这仍需线上抽样。

## 结论

领域规则层本身不足以解决长篇角色扮演的混乱。它擅长约束单个动作，但如果没有战役阶段，系统仍不知道“这一回合在整段故事里处于哪里”。有效组合是：

`战役阶段（跨场因果） → 领域事务（单场权威状态） → 视觉快照（当前可见结果） → AI 开放层（非必要表达）`

这套结构比“让模型同时写故事、发状态命令、决定镜头”可靠，因为必要状态只有一个本地写入者；同时仍保留自由输入和 AI 的表达空间。后续游戏可复用这个模式，但不应机械套用四世界或四阶段数字：阶段数量必须来自具体游戏的体验结构。

## 后续复用门禁

- 必须先写出不可被模型省略的主线里程碑和唯一奖励。
- 每个受管回合必须原子提交正文、状态、合法后续行动和视觉快照。
- 主线事务期间禁止再叠加独立随机事件，除非它已进入同一事务设计。
- 图片提示必须描述事务后的唯一当前现场，不得从整段历史自由摘要。
- 图片等待、失败和重试必须有独立叙事语义；旧图不得无标记冒充当前图。
- 测试必须覆盖逐回合重载、自由输入映射、重复奖励、两个移动视口和完整终局。
